# SkyVanta AI — Demonstration & Portfolio Asset Checklist

## Overview
This checklist outlines the visual assets, screenshots, and recording checkpoints for showcasing **SkyVanta AI** in technical portfolios, MNC presentations, and GitHub releases.

---

## Screenshot & Visual Asset Matrix

| # | Asset Target | Description / Verification Point | Sanitization Check |
|---|---|---|---|
| **1** | **GitHub Repository Header** | Clean repository overview, release tags, and architecture badge summary. | No private URLs or tokens. |
| **2** | **System Architecture Diagram** | High-resolution render of the V1–V9 robotics core and D1–D9 deployment layers. | Validated mermaid render. |
| **3** | **Interactive API Docs (`/docs`)** | Swagger UI displaying `Health`, `Release`, `Observability`, `System`, `Scenarios`, `Simulation`, and `Telemetry` tags. | Public schema only; no internal IPs. |
| **4** | **Infrastructure Health Endpoint** | `GET /health` JSON response verifying `status: "healthy"` and `safety_boundary_enforced: true`. | Verified payload. |
| **5** | **Scenario Execution Output** | Terminal or JSON output for `POST /api/v1/scenarios/run` (`nominal_landing`, `SUCCESS_LANDED`). | Sanitized token headers. |
| **6** | **WebSocket Telemetry Stream** | Live terminal or UI streaming 20 Hz JSON packets showing position, velocity, and landing phase. | Masked API key query parameter. |
| **7** | **Hardened Docker Container** | `docker ps` and non-root execution logs confirming `UID 1000` and dropped capabilities. | No host system environment leaks. |
| **8** | **Operational Observability Metrics** | `GET /api/v1/metrics` payload showing latency percentiles (p50/p95/p99) and resource usage. | Bounded memory stats. |
| **9** | **Safety FSM Abort Decision** | Log output or state diagram demonstrating transition to `ABORTING` on target loss. | Explainable reason codes. |
| **10** | **Digital Twin Simulation Trajectory** | Quantitative landing error and trajectory report generated by `ScenarioReportGenerator`. | Accurate simulation metrics. |

## Pre-Recording Security & Sanitization Protocol
Before capturing video recordings or screenshots:
1. Ensure all API keys shown in examples use sanitized test fixtures (e.g. `sk_test_admin_key_12345` or masked `sk_test_...345`).
2. Verify that no `.env` file contents, private SSH keys, or internal token secrets are visible.
3. Confirm that all endpoints indicate simulation-only status (`hardware_access: false`).
